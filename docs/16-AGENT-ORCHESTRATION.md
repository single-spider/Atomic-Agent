# Agent role dispatch and dashboard (experimental)

The control-plane now exposes **eight typed agent roles** through `atomic_agent.agents.PROFILES`: Business Analyst, Solution Architect, Developer, Test Engineer, Code Reviewer, Security Reviewer, Defect Resolver and Release Assurance. Each declares required output keys and a role description; only Developer and Defect Resolver may propose code edits.

## Harness boundary

`HarnessAdapter.invoke(profile, context)` is the single role-dispatch interface. The default `NoHarness` rejects every live request until an approved runtime is provided. `SyntheticAgentForTests` provides **deterministic, hardcoded fixture proposals for integration tests only**; its outputs are not generated by an LLM and can never count as tool evidence or release readiness.

`Orchestrator.analyze`, `.design`, `.propose_tests`, `.propose_code`, `.inspect`, `.summarize` and `.validate_in_docker` define the basic calls. Requirements and design proposals are persisted only in stages permitting them. A design cannot proceed to code until a named operator approves its exact hash. Coding proposals are marked `UNVERIFIED_AGENT_PROPOSAL`; mere agent-provided revision/diff identifiers **must be verified independently** before validation. Generated tests are proposals; golden tests determine acceptance.

## Dashboard

The root `/` path serves a small no-build SDLC dashboard. An operator can enter a local auth token in the browser (kept only in page memory), create a requirement, submit JSON artifacts, approve versioned artifacts, evaluate gates, inspect current status and see an append-only workflow timeline. The UI renders untrusted content with `textContent` rather than HTML injection. This is a **local development interface**, not multi-tenant RBAC or production authentication.

The API also adds optional role-trigger endpoints:

- `POST /runs/{id}/agent/analyze`
- `POST /runs/{id}/agent/design`
- `POST /runs/{id}/agent/propose-tests`

They fail closed with HTTP 409 by default because no harness has been configured. Integration tests inject `SyntheticAgentForTests` programmatically to prove the stage and approval boundaries without model calls.
